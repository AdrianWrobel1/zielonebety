## 2. Identified Architectural Couplings & Target Mitigations

### 1. Coordinated Pre-Discovery Inside Orchestrator (P1)
* **Current Issue:** `ProductionScanOrchestrator` currently executes an inline pre-discovery step (lines 530–784) that parses overview payloads, runs normalization, and calls candidate generator and event matcher before launching the main provider execution loop.
* **Target Architecture:** Extract into a dedicated `CoordinatedDetailSelectionPlanner` stage component that consumes discovery results and outputs an immutable `DetailAcquisitionPlan`.

### 2. Multiplicity of Market Categorization Functions (P1)
* **Current Issue:** `_categorize_market_type` existed in `orchestration/scan_orchestrator.py` while `extract_canonical_market_key` and `is_allowed_market_family` existed in `normalization/`.
* **Target Architecture:** `normalization.market_identity.extract_canonical_market_key` and `normalization.market_scope.is_allowed_market_family` must be the SOLE authoritative sources for market classification.

### 3. Discovery Cache Mutation on Provider Instances (P2)
* **Current Issue:** Orchestrator sets `provider._discovered_items_cache = discovered` directly on provider instances to prevent duplicate HTTP calls.
* **Target Architecture:** Make caching explicit in the provider interface contract (`provider.set_discovered_items()`).
